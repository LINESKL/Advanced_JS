# Задача 1: Паттерн Singleton
## Управление конфигурацией приложения

### Описание
Реализация паттерна Singleton для создания единого менеджера конфигурации приложения. ConfigManager гарантирует наличие только одного экземпляра класса независимо от способа создания.

### Цели задачи
- Реализовать класс ConfigManager с паттерном Singleton
- Обеспечить единственность экземпляра при любом способе создания
- Протестировать согласованность данных между экземплярами
- Сравнить классовый и модульный подходы к реализации Singleton

### Реализация

**singleton.js** - класс ConfigManager:
- Проверка существующего экземпляра в конструкторе
- Статический метод `getInstance()` для получения экземпляра
- Методы `get()`, `set()`, `getAll()` для работы с конфигурацией
- Хранение единственного экземпляра в статическом свойстве

**config.js** - модульный singleton:
- Использование модульной системы ES6 для создания singleton
- Экспорт единственного экземпляра класса

**test.js** - тестирование паттерна:
- Создание экземпляров разными способами (getInstance, new)
- Проверка идентичности экземпляров
- Тестирование сохранения данных между экземплярами
- Сравнение классового и модульного подходов

### Ключевые особенности

| Аспект | Реализация |
|--------|------------|
| **Создание экземпляра** | Через статический метод getInstance() и конструктор |
| **Хранение** | Статическое свойство ConfigManager.instance |
| **Защита** | Проверка в конструкторе, возврат существующего экземпляра |
| **Доступ к данным** | Методы get/set для безопасной работы с конфигурацией |

### Преимущества паттерна
- Контролируемый доступ к единственному экземпляру
- Гарантия согласованности данных
- Глобальная точка доступа к ресурсу
- Ленивая инициализация (создание при первом обращении)
