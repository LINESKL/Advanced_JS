## 1.Какие два сценария ты реализовал и почему?

#### "Я реализовал сценарии 03 (Observer) и 05 (Command). Я выбрал их, потому что они наглядно демонстрируют решение проблем коммуникации: Observer позволяет избежать жестких связей между UI-компонентами, а Command превращает действия пользователя в объекты, что критически важно для функций Undo/Redo в современных приложениях."

## 2. Для 4-х нереализованных сценариев укажи главную подсказку (clue) из описания:

### Scenario 01: "exactly ONE configuration store" (строго ОДНО хранилище) — это прямой признак Singleton.

### Scenario 02: "modern interface expected... legacy call" (ожидается современный интерфейс при наличии старого) — признак Adapter.

### Scenario 04: "same construction steps... different representations" (одни и те же шаги для разных форматов) — признак Builder.

### Scenario 06: "50,000 particles... share data to save memory" (50 тыс. частиц, разделение данных для экономии памяти) — признак Flyweight.

## 3. Что нового ты узнал?

#### "Я понял, что категоризация — это не просто теория, а инструмент для фильтрации решений. Теперь, видя проблему 'раздутой памяти', я сразу ищу решение в Структурных паттернах (Flyweight), а не пытаюсь переписать логику создания объектов."
