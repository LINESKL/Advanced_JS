# Документация процесса рефакторинга — Лабораторная работа 4.2

В данном документе подробно описаны изменения, внесенные в ходе рефакторинга устаревшего кода (Implementation B), и обосновано применение выбранных паттернов проектирования.

## 1. Что было изменено и почему?
В процессе работы исходный монолитный код был разделен на независимые модули. Основные изменения:
*   **Глобальные переменные:** Все переменные (`cart`, `products`, `taxRate`) были удалены из глобальной области видимости и перемещены внутрь приватных областей соответствующих модулей.
*   **Логическое разделение:** Код разделен на три функциональных блока:
    1.  `Config` (Настройки).
    2.  `Utils` (Утилиты для форматирования и валидации).
    3.  `Store` (Бизнес-логика товаров и корзины).
*   **Устранение дублирования:** Несколько функций форматирования цены были заменены одной универсальной функцией в модуле `Utils` (принцип DRY).

## 2. Как паттерн «Модуль» решает проблемы кода (Гл. 7)
Применение **Module Pattern** через использование IIFE (немедленно вызываемых функций) позволило достичь следующих целей:
*   **Инкапсуляция данных:** Использование приватных переменных (например, `let _cart = []`) гарантирует, что состояние корзины нельзя изменить напрямую из консоли браузера. Доступ к данным возможен только через публичные методы (`addItem`, `processOrder`).
*   **Управление зависимостями:** Модули получают необходимые данные (например, налоговую ставку) не из глобальной среды, а через явную передачу других модулей в качестве аргументов. Это снижает жесткую связь (Tight Coupling) между компонентами.
*   **Чистое API:** Наружу выставлены только необходимые функции, что упрощает использование кода другими разработчиками.

## 3. Применение паттерна «Пространство имен» (Гл. 11)
Для организации модулей была создана иерархическая структура под единым глобальным объектом `MyApp`:
*   `MyApp.Config` — централизованные настройки.
*   `MyApp.Utils` — вспомогательный функционал.
*   `MyApp.Modules.Store` — основная логика приложения.

**Почему это важно:**
*   **Предотвращение коллизий:** Теперь в глобальной области видимости существует только один идентификатор (`MyApp`), что сводит риск конфликтов с другими библиотеками к минимуму.
*   **Улучшение организации:** Пространство имен создает логическую вложенность, облегчая поиск нужной функции в большом проекте.

## 4. Достигнутые преимущества
1.  **Масштабируемость:** Теперь мы можем легко добавить новый функционал (например, модуль `UserAuth`), просто расширив объект `MyApp.Modules`, не затрагивая существующий код.
2.  **Безопасность:** Внутренние состояния приложения защищены замыканиями, что предотвращает случайные или злонамеренные изменения данных.
3.  **Читаемость:** Код стал самодокументированным благодаря четкому разделению зон ответственности.

## 5. Соответствие техническим требованиям
*   Использован современный стандарт JavaScript (ES6+): `const`, `let`, стрелочные функции.
*   Соблюдена нотация `camelCase` для именования всех переменных и функций.
*   Код полностью executable (исполняемый) и сохраняет оригинальную функциональность системы заказов.
