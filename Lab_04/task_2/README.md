# Lab 4.2: Рефакторинг legacy-кода

## Обзор
Данная часть лабораторной работы посвящена практическому рефакторингу устаревшего кода интернет-магазина (Implementation B) с применением паттернов проектирования для создания современной, модульной архитектуры.

## Цель
Продемонстрировать навыки рефакторинга legacy-кода, применяя профессиональные паттерны проектирования JavaScript для устранения антипаттернов и создания чистой, поддерживаемой архитектуры приложения.

## Структура файлов в task_2:

### legacy_code.js
Исходный код интернет-магазина с антипаттернами: глобальные переменные, жесткая связь компонентов, дублирование кода, отсутствие инкапсуляции.

### refactoring_plan.md
План рефакторинга: анализ проблем, стратегия улучшения, описание применяемых паттернов и архитектуры модулей.

### refactoring_documentation.md
Документация процесса: описание модулей, обоснование решений, примеры использования, сравнение до/после.

### refactored_modules/
**Новая модульная архитектура приложения:**

#### namespace.js
Базовое пространство имен: глобальный объект `MyApp` с вложенными пространствами.

#### module1.js — Config Module
Централизованное хранение констант: налоги, валюта, стоимость доставки.

#### module2.js — Utils Module
Переиспользуемые функции: форматирование, валидация, вспомогательные методы.

#### module3.js — Cart/Core Module
Бизнес-логика: управление товарами, расчет стоимости с налогами, приватное состояние.

#### main.js
Точка входа: инициализация и координация работы модулей.

## Применяемые паттерны проектирования

### 1. Namespace Pattern
Организация кода под единым глобальным объектом `MyApp` для предотвращения загрязнения глобальной области и создания логической структуры.

### 2. Module Pattern
Использование IIFE для создания приватных областей видимости, инкапсуляции данных и предоставления публичного API.

### 3. Revealing Module Pattern
Явное определение публичного интерфейса с скрытием приватной реализации.

## Ключевые улучшения

- Код разделен на независимые модули
- Единое глобальное пространство имен
- Инкапсуляция данных и публичное API
- Устранено дублирование кода
- Централизованная конфигурация

## Сравнение до/после

| Аспект | До рефакторинга | После рефакторинга |
|--------|----------------|-------------------|
| Глобальные переменные | 10+ переменных | 1 объект (`MyApp`) |
| Структура | Монолитный код | 5 модулей |
| Инкапсуляция | Отсутствует | Полная |
| Дублирование кода | Высокое | Отсутствует |
| Тестируемость | Низкая | Высокая |
| Поддерживаемость | Сложная | Простая |
| Связанность | Жесткая | Слабая |
| Конфигурируемость | Хардкод | Централизованная |

## Результаты рефакторинга

Устранены критичные антипаттерны, создана модульная архитектура с применением профессиональных паттернов проектирования. Улучшена поддерживаемость и расширяемость кода за счет инкапсуляции и разделения ответственности.

**Метрики:**
- Связанность: снижена с высокой до низкой
- Когезия: повышена внутри модулей
- Цикломатическая сложность: уменьшена
- Переиспользуемость: утилиты можно применять в других проектах

## Примеры использования

```javascript
// Инициализация приложения
MyApp.init();

// Добавление товара в корзину
MyApp.Modules.Cart.addItem({
  id: 1,
  name: "Laptop",
  price: 1200
});

// Получение общей стоимости
const total = MyApp.Modules.Cart.getTotal();
console.log(MyApp.Utils.formatPrice(total));
```
