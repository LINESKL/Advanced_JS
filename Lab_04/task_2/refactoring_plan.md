# План рефакторинга — Лабораторная работа 4.2

## 1. Введение
Цель данного рефакторинга — переработать устаревший код интернет-магазина (Implementation B) в современное, модульное приложение. Мы устраним глобальные переменные и уменьшим жесткую зависимость функций друг от друга, используя профессиональные паттерны проектирования JavaScript.

## 2. Анализ проблем (на основе Гл. 4)
Текущая реализация содержит несколько критических антипаттернов:
*   **Загрязнение глобального пространства имен:** Переменные `cart`, `user`, `taxRate` и другие объявлены глобально, что создает риск конфликтов имен.
*   **Жесткая связь (Tight Coupling):** Бизнес-логика (добавление товаров) смешана с вызовами обновления интерфейса и сохранением в хранилище, что делает компоненты зависимыми друг от друга.
*   **Нарушение принципа DRY:** Функции форматирования (formatPrice, formatAmount) дублируют одну и ту же логику.
*   **Отсутствие инкапсуляции:** Список товаров и корзина открыты для прямого изменения извне, что небезопасно.

## 3. Стратегия рефакторинга
Для исправления этих проблем будут применены следующие паттерны из книги Э. Османи:
1.  **Паттерн "Пространство имен" (Namespace Pattern, Глава 11):** Вся логика будет перемещена под единый глобальный объект `MyApp`. Это предотвратит загрязнение глобальной области. Мы будем использовать вложенные пространства имен (например, `MyApp.Modules`, `MyApp.Utils`).
2.  **Паттерн "Модуль" (Module Pattern, Глава 7):** Мы будем использовать IIFE (самовызывающиеся функции) для создания приватных областей видимости. Это гарантирует, что такие данные, как массив корзины, останутся скрытыми и будут доступны только через публичное API модуля.

## 4. Проектируемая архитектура модулей
Код будет разделен на три логических модуля:
*   **Модуль конфигурации (Config):** Централизованное хранилище для констант, таких как налоговая ставка (`taxRate`), валюта и стоимость доставки.
*   **Модуль утилит (Utils):** Переиспользуемые функции для форматирования цен и валидации вводимых данных.
*   **Модуль бизнес-логики (Cart/Core):** Управляет товарами, добавлением в корзину и расчетом итоговой стоимости.

## 5. Ожидаемые преимущества
*   **Удобство поддержки:** Изменения в логике налогов потребуют обновления только в модуле Config.
*   **Безопасность:** Приватное состояние предотвращает прямое манипулирование корзиной покупок из консоли браузера.
*   **Тестируемость:** Модули можно тестировать независимо от глобального состояния приложения.
