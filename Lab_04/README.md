# Lab 4 — Anti-Patterns & Refactoring

### Identifying and Fixing Anti-Patterns in JavaScript

</div>

## Описание

Изучение антипаттернов в JavaScript и методов рефакторинга legacy-кода. Практический анализ проблемного кода, идентификация антипаттернов и их устранение с помощью паттернов проектирования.

## Задания

### Task 1 — Anti-Pattern Analysis

**Директория:** `task_1/`

Анализ проблемного JavaScript-кода с идентификацией антипаттернов, их классификацией и оценкой влияния на качество и поддерживаемость кода.

#### Компоненты задания:

**anti_patterns_identified.md**
- Детальная идентификация всех найденных антипаттернов
- Указание конкретных строк кода с проблемами
- Описание каждого антипаттерна
- Объяснение негативного влияния на код

**anti_patterns_classification.md**
- Классификация антипаттернов по категориям
- Группировка похожих проблем
- Приоритизация по степени критичности
- Рекомендации по устранению

**impact_assessment.md**
- Оценка влияния антипаттернов на проект
- Анализ последствий для поддерживаемости
- Оценка технического долга
- Метрики качества кода

#### Основные антипаттерны:
- Global Namespace Pollution — загрязнение глобального пространства
- Code Duplication — дублирование логики
- Tight Coupling — жесткая связь компонентов
- Magic Numbers & Strings — хардкод значений

### Task 2 — Code Refactoring

**Директория:** `task_2/`

Практический рефакторинг устаревшего кода интернет-магазина с применением паттернов проектирования для создания современной модульной архитектуры.

#### Компоненты задания:

**legacy_code.js**
- Исходный проблемный код (Implementation B)
- Пример legacy-кода с множественными антипаттернами
- Базис для анализа и рефакторинга

**refactoring_plan.md**
- Детальный план рефакторинга
- Анализ проблем текущей реализации
- Стратегия улучшения кода
- Описание применяемых паттернов
- Проектируемая архитектура модулей

**refactoring_documentation.md**
- Полная документация процесса рефакторинга
- Детальное описание каждого модуля
- Обоснование архитектурных решений
- Примеры использования новой структуры
- Сравнение до/после рефакторинга

**refactored_modules/**
- `namespace.js` — Базовое пространство имен приложения
- `module1.js` — Модуль конфигурации (Config)
- `module2.js` — Модуль утилит (Utils)
- `module3.js` — Модуль бизнес-логики (Cart/Core)
- `main.js` — Главный файл инициализации

#### Применяемые паттерны:
- **Namespace Pattern** — единое пространство имен `MyApp`
- **Module Pattern (IIFE)** — приватные области видимости
- **Revealing Module Pattern** — явный публичный API

## Результаты работы

По завершении лабораторной работы достигнуты следующие результаты:

1. **Навыки анализа:**
   - Умение распознавать антипаттерны в коде
   - Способность оценивать качество кода
   - Понимание последствий плохих практик

2. **Практика рефакторинга:**
   - Опыт работы с legacy-кодом
   - Применение паттернов для улучшения структуры
   - Создание модульной архитектуры

3. **Архитектурное мышление:**
   - Проектирование чистой структуры кода
   - Разделение ответственности между модулями
   - Создание масштабируемых решений

4. **Профессиональное развитие:**
   - Понимание важности качества кода
   - Навыки работы в команде над legacy-проектами
   - Умение документировать архитектурные решения
