# Impact Assessment of Anti-Patterns

В данном отчете проводится оценка влияния выявленных антипаттернов на жизненный цикл программного обеспечения.

---

### 1. Global Namespace Pollution
*   **Maintainability:** Низкая. Очень сложно отследить, где и когда меняется значение переменной, так как доступ к ней открыт отовсюду.
*   **Scalability:** Низкая. С ростом проекта вероятность того, что два разработчика назовут разные переменные одним именем (например, `config`), стремится к 100%.
*   **Performance:** Минимальное влияние, однако поиск переменных в глобальной области видимости работает чуть медленнее, чем в локальной.
*   **Team Collaboration:** Высокий риск конфликтов. Разработчики могут случайно перезаписывать данные друг друга.
*   **Severity:** **High** (Высокий).

### 2. Code Duplication (Validation Logic)
*   **Maintainability:** Очень низкая. Любое изменение бизнес-логики (например, новые требования к безопасности email) требует правок в нескольких файлах/функциях.
*   **Scalability:** Низкая. Дублирование увеличивает объем кодовой базы («bloated code»), не принося новой функциональности.
*   **Performance:** Незначительное увеличение размера файла, что может замедлить загрузку скрипта.
*   **Team Collaboration:** Создает путаницу. Разработчики не знают, какую из функций-дубликатов использовать как «официальную».
*   **Severity:** **Medium** (Средний).

### 3. Configuration Scattered Throughout Code
*   **Maintainability:** Сложная. Чтобы сменить URL сервера, нужно проводить поиск по всему проекту («grep»), что чревато пропусками.
*   **Scalability:** Средняя. Переход на новые окружения (Staging/Production) превращается в ручной и рискованный процесс.
*   **Performance:** Нет влияния.
*   **Team Collaboration:** Повышает порог входа для новых разработчиков, так как настройки не лежат в одном очевидном месте.
*   **Severity:** **Medium** (Средний).

### 4. Event Handlers as Global Functions
*   **Maintainability:** Средняя. Глобальные функции захламляют `window`, делая отладку в консоли браузера неудобной.
*   **Scalability:** Низкая. Трудно строить сложные интерфейсы (SPA), когда логика событий не инкапсулирована в компоненты или модули.
*   **Performance:** Нет влияния.
*   **Team Collaboration:** Риск того, что другой скрипт переопределит глобальную функцию `onLoginClick`.
*   **Severity:** **Low/Medium** (Низкий/Средний).

### 5. Data Processing with Tight Coupling
*   **Maintainability:** Критически низкая. Изменение в логике кэширования может «сломать» обновление UI или валидацию, хотя они логически не должны зависеть друг от друга.
*   **Scalability:** Очень низкая. Невозможно внедрять новые модули, так как текущие функции слишком сильно «прошиты» друг в друга.
*   **Performance:** Может привести к лишним вызовам функций обновления интерфейса, даже если данные не изменились.
*   **Team Collaboration:** Невозможно проводить модульное тестирование (Unit Testing), так как функцию нельзя изолировать от глобального состояния.
*   **Severity:** **Critical** (Критический).

---

### Приоритизация по степени важности

| Priority | Anti-Pattern | Action Required |
| :--- | :--- | :--- |
| **Critical** | Data Processing with Tight Coupling | Немедленный рефакторинг, разделение на независимые модули. |
| **High** | Global Namespace Pollution | Группировка в Namespace. |
| **Medium** | Code Duplication | Применение принципа DRY через утилитарные модули. |
| **Medium** | Configuration Scattered | Вынос всех констант в единый объект `Config`. |
| **Low** | Event Handlers as Globals | Инкапсуляция логики событий внутри модулей. |

---

### Заключение
Как отмечает Эдди Османи (Ch. 4): *"Knowledge of anti-patterns is critical for success. Once we learn to recognize such anti-patterns, we can refactor our code to negate them..."*. Выявленные антипаттерны создают значительный **Technical Debt** (технический долг), который в будущем замедлит разработку и увеличит стоимость поддержки проекта.
