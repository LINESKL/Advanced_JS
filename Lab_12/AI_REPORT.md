### Lab 12.1: Web Workers - Background Processing

## 1. Информация об использовании AI 
- **Инструмент:** Claude Code (Sonnet 4)

## 2. Конкретные промпты

### Промпт 1:
"Как правильно реализовать Web Worker для вычисления простых чисел с отправкой прогресса выполнения?"

**Что получил:** Объяснение использования `self.postMessage()` для отправки промежуточных результатов. AI показал, как структурировать сообщения с типами (`PROGRESS`, `PRIMES_RESULT`) и как отправлять обновления каждые N найденных чисел, чтобы не перегружать главный поток.

### Промпт 2:
"Как использовать Transferable Objects при передаче ImageData между главным потоком и воркером для обработки изображений?"

**Что получил:** Разъяснение о передаче `ArrayBuffer` через второй параметр `postMessage()`. AI объяснил, что это позволяет передать владение данными воркеру без копирования, что критично для больших изображений. Пример: `postMessage({data}, [data.buffer])`.

### Промпт 3:
"Как создать менеджер для управления несколькими воркерами и отслеживания их статистики?"

**Что получил:** Паттерн Worker Pool с использованием `Map` для хранения экземпляров воркеров. AI предложил создать класс `WorkerManager` с методами `createWorker()`, `terminateWorker()` и `recordTask()` для сбора метрик производительности.

## 3. Модификация и проверка
- **Реализация воркеров:** Самостоятельно добавил три типа воркеров (Prime, Sort, Image) с разными алгоритмами.
- **UI интеграция:** Создал интерфейс с прогресс-барами и статистикой, чтобы визуально показать, что главный поток не блокируется.
- **Оптимизация:** Добавил проверку простоты числа через √n вместо перебора всех делителей, что ускорило вычисления в 10+ раз.

### Lab 12.2: Service Workers & Progressive Web App

## 1. Информация об использовании AI
- **Инструмент:** Claude Code (Sonnet 4)
- **Дата:** 2026-04-22

## 2. Конкретные промпты

### Промпт 1:
"Как реализовать стратегию Cache-First для статических ресурсов и Network-First для API запросов в Service Worker?"

**Что получил:** Код с обработкой события `fetch`, где проверяется тип запроса. AI показал, как использовать `caches.match()` для поиска в кэше и `fetch()` с fallback на кэш при ошибке сети. Также объяснил важность клонирования ответа через `response.clone()` перед кэшированием.

### Промпт 2:
"Как правильно управлять версиями кэша и очищать устаревшие данные при обновлении Service Worker?"

**Что получил:** Паттерн с константами `CACHE_NAME` и `RUNTIME_CACHE`. AI показал, как в событии `activate` получить все имена кэшей через `caches.keys()` и удалить те, которые не соответствуют текущей версии. Это предотвращает накопление старых данных.

### Промпт 3:
"Как реализовать offline-очередь для действий пользователя, которые нужно синхронизировать при восстановлении связи?"

**Что получил:** Идею с массивом `offlineQueue` и слушателями событий `online`/`offline`. AI предложил сохранять действия со статусом `pending` и менять его на `synced` после успешной отправки. Также упомянул Background Sync API для более надежной синхронизации.

## 3. Модификация и проверка
- **Lifecycle управление:** Самостоятельно добавил кнопки для обновления, очистки кэша и отмены регистрации SW.
- **Cache Inspector:** Реализовал просмотр всех закэшированных ресурсов с группировкой по именам кэшей.
- **PWA функции:** Добавил обработку события `beforeinstallprompt` для показа баннера установки приложения.
- **Тестирование offline:** Проверил работу через DevTools Network → Offline, убедился, что приложение загружается из кэша.

## 4. Что узнал
- Понял жизненный цикл Service Worker: install → activate → fetch.
- Узнал о разных стратегиях кэширования и когда какую использовать.
- Научился работать с Cache API и управлять версиями кэша.
- Осознал важность HTTPS для Service Workers (или localhost для разработки).
- Изучил, как создать полноценное PWA с манифестом и возможностью установки.
