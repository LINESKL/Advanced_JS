## Обзор

В данном задании реализован базовый сценарий Server-Side Rendering и Hydration: HTML генерируется на сервере, начальные данные инжектируются в страницу, после чего клиентский скрипт делает интерфейс интерактивным.

## Файлы

- `server/index.js` — Node.js сервер, SSR-разметка, инъекция состояния и раздача клиентского скрипта.

## Ключевые механизмы

### 1. Server-Side Rendering (SSR)
Сервер при запросе к `/` получает пользовательские данные (симуляция БД) и формирует готовый HTML с уже отображаемым профилем пользователя.

### 2. State Transfer
Начальное состояние передается в браузер через глобальную переменную `window.__INITIAL_STATE__`, что позволяет клиенту продолжить работу без повторного запроса данных на старте.

### 3. Hydration Process
Клиентский код (endpoint `/client.js`) находит целевые DOM-узлы, снимает loading-состояние, активирует кнопку и навешивает обработчики событий для переключения статуса Offline/Online.

### 4. UX-Demonstration
Искусственная задержка перед гидрацией показывает разницу между:
- **FCP (First Contentful Paint)** — контент уже виден (SSR)
- **TTI (Time To Interactive)** — интерфейс становится интерактивным позже (Hydration)

## Пример запуска

```bash
cd task_1/server
node index.js
```

После запуска открыть в браузере: `http://localhost:3000`

## Результаты

1. Понимание полного цикла SSR → State Transfer → Hydration
2. Навык привязки клиентской логики к уже отрендеренному DOM
3. Практический опыт построения SSR-страницы без фреймворков
