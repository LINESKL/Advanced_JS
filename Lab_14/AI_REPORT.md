## 2. Конкретные промпты

### Промпт 1:
"Напиши полный код для Lab 14.1 на Node.js. Нужно создать сервер, который имитирует получение данных из БД, рендерит HTML строку с начальным состоянием в `window.__INITIAL_STATE__` и отдает клиентский скрипт для гидрации."

**Что получил:** Полный код сервера с использованием модуля `http`. AI реализовал функцию `getClientCode()`, которая возвращает строку с JavaScript-кодом, и показал, как вставить JSON-данные пользователя прямо в тег `<script>` внутри HTML-шаблона.

### Промпт 2:
"Как в процессе гидрации правильно найти DOM-узлы и добавить им интерактивность, не перезаписывая весь HTML, созданный сервером?"

**Что получил:** Объяснение процесса "оживления" (hydration). AI предложил использовать `document.getElementById` для поиска конкретных элементов (кнопка, статус) и метод `addEventListener`. Также был добавлен `setTimeout`, чтобы наглядно увидеть разницу между моментом появления контента (FCP) и моментом, когда кнопка становится кликабельной (TTI).

### Промпт 3:
"Почему важно использовать `JSON.stringify()` при передаче данных с сервера на клиент через `window.__INITIAL_STATE__`?"

**Что получил:** Разъяснение о сериализации данных. AI объяснил, что это превращает объект JavaScript в строку, которую браузер может безопасно прочитать, а также упомянул о рисках XSS-атак при неправильной обработке данных.

## 3. Модификация и проверка
- **Логика гидрации:** Я изменил текст на кнопке и добавил смену цвета текста статуса (`statusBadge.style.color`), чтобы визуально выделить переход из "Offline" в "Online".
- **Задержка:** Установил задержку гидрации в 1000мс, чтобы в консоли браузера было четко видно сообщение "DOM Ready", а затем, спустя секунду, сообщение о завершении гидрации.
- **Обработка ошибок:** Добавил проверку `if (!profileNode...)`, чтобы скрипт не падал, если сервер по какой-то причине не отрендерил нужные ID.

## 4. Что узнал
- Понял разницу между "мертвым" HTML (SSR) и интерактивным приложением.
- Узнал, что такое **Hydration Bottleneck**: браузеру нужно время на загрузку и выполнение JS, прежде чем страница станет функциональной.
- Научился передавать состояние (state) между сервером и клиентом без дополнительных API-запросов при первой загрузке.

### Lab 14.2: Component Islands Architecture Simulation

## 1. Информация об использовании AI
- **Инструмент:** Google Gemini 
- **Дата:** 2026-04-15

## 2. Конкретные промпты

### Промпт 1:
"Как реализовать Islands Architecture на чистом JavaScript? Мне нужен движок (engine), который находит элементы с атрибутом `data-island-type` и подключает к ним функции из реестра `IslandRegistry`."

**Что получил:** Паттерн "Стратегия" (Strategy Pattern). AI предложил создать объект `IslandRegistry`, где ключи — это типы островов, а значения — функции инициализации. Это обеспечивает изоляцию кода (замыкания), так как переменные внутри одного острова не видны другому.

### Промпт 2:
"Как использовать `IntersectionObserver` для ленивой гидрации островов, чтобы скрипт запускался только когда пользователь доскроллит до компонента?"

**Что получил:** Код с созданием `new IntersectionObserver`. AI объяснил, как использовать `entry.isIntersecting` и метод `observer.unobserve()`, чтобы гидрация происходила только один раз при появлении острова в области видимости (threshold 0.1).

### Промпт 3:
"Как сделать так, чтобы переменная `count` в острове Counter не конфликтовала с другими компонентами на странице?"

**Что получил:** Совет использовать функциональные замыкания (closures). Каждый раз, когда вызывается функция из реестра для конкретного контейнера, создается своя область видимости для переменных.

## 3. Модификация и проверка
- **Реализация островов:** Самостоятельно разработал остров `color-picker`, который меняет фоновый цвет превью-бокса при нажатии на кнопки с `data-color`.
- **Оптимизация:** Настроил `rootMargin` в обсервере, чтобы остров начинал загружаться чуть раньше (за 100px до появления на экране), делая процесс бесшовным для пользователя.
- **Структура:** Разделил код на `index.html` и `islands-engine.js` для соблюдения принципов чистого кода.

## 4. Что узнал
- Изучил концепцию "островов" (Islands Architecture), которая используется в современных фреймворках типа Astro.
- Понял, как минимизировать объем JS на клиенте, загружая интерактивность только там, где она действительно нужна.
- Научился использовать `data-` атрибуты для связи HTML-разметки с JavaScript-логикой.
