# Lab 14 — Modern Rendering Architectures

### SSR Hydration & Islands Architecture

</div>

## Описание

Изучение современных подходов к рендерингу интерфейсов в веб-приложениях: серверный рендеринг с последующей гидрацией (SSR + Hydration) и архитектура интерактивных островов (Islands Architecture). В работе реализованы практические примеры разделения статического и интерактивного контента для улучшения производительности.

## Задания

### Task 1 — SSR Hydration Basics

Реализация Node.js HTTP-сервера, который рендерит HTML на сервере, передает начальное состояние в клиент и затем выполняет гидрацию DOM-узлов на стороне браузера.

**Ключевые аспекты:**
- Серверная генерация HTML (SSR)
- Инъекция `window.__INITIAL_STATE__` для передачи данных
- Гидрация заранее отрендеренного DOM после `DOMContentLoaded`
- Демонстрация разницы между FCP и TTI через искусственную задержку

### Task 2 — Islands Architecture

Реализация клиентского движка островов, где только отдельные интерактивные блоки получают JavaScript-логику, а остальная страница остается статической.

**Ключевые аспекты:**
- Реестр островов (`IslandRegistry`) по типу компонента
- Поиск островов через `data-island-type`
- Ленивая гидрация через `IntersectionObserver`
- Независимая инициализация интерактивных виджетов (Counter, Color Picker)

## Применяемые технологии

| Технология | Использование |
|-----------|----------|
| **Node.js HTTP** | Серверный рендеринг HTML |
| **SSR + Hydration** | Быстрый первый рендер + последующая интерактивность |
| **IntersectionObserver** | Отложенная инициализация островов |
| **ES Modules** | Подключение клиентского движка островов |
| **Vanilla JavaScript** | Реализация интерактивных компонентов |

## Результаты работы

По завершении лабораторной работы достигнуты следующие результаты:

1. **SSR и гидрация:**
   - Понимание процесса передачи состояния с сервера на клиент
   - Навык связывания предрендеренного DOM с клиентской логикой

2. **Islands-подход:**
   - Разделение страницы на статическую и интерактивную части
   - Ленивая загрузка поведения только для видимых компонентов

3. **Производительность:**
   - Снижение объема необязательного JS для статического контента
   - Улучшение управляемости клиентской инициализации
